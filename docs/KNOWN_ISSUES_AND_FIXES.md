# Known issue and risk register

Last reviewed: November 27, 2026

This register summarizes recurring or release-significant issues seen during
OpenCourts web, Android, iOS, and backend development/testing. Detailed feature
history and incident evidence remain in the linked handovers; this index does
not replace or delete that history. “Owner-confirmed” means the owner reported
the result, while “source fixed” means code was changed but the installed
release has not yet been verified. Environment IDs and statuses can change;
check the current handoffs before acting.

## Working rules learned from these incidents

- Preview success does not prove Production configuration/schema parity. Compare
  bindings, environment overrides, Worker versions, migration ledger, API origin,
  and authenticated response behavior explicitly.
- Do not treat a Pages deployment as an iOS binary update. Record the actual
  App Store/TestFlight build and source/archive mapping when available.
- Do not infer user identity from a display name or test a real account through
  synthetic writes. Use consented actions and privacy-safe correlation.
- Keep iOS-only APNs changes in the native sender path; do not disturb working
  website Web Push or Android notification behavior.
- Record whether a fix is source-only, deployed, owner-reported, or independently
  verified. Preserve dated feature history and link new evidence here.
